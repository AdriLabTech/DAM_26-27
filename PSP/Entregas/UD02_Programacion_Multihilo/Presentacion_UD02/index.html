01 · El hilo
03

Un hilo es una vía de ejecución
dentro de un proceso.

Proceso: programa en ejecución con su propia memoria.   Hilo: comparte esa memoria, y por eso es más ligero… y más peligroso.

01 · El hilo
04

Más rendimiento,
a cambio de más cuidado.

+ Ventajas

  • Aprovechan todos los núcleos.
  • Menos tiempo total: tareas en paralelo.
  • Interfaz fluida mientras algo trabaja detrás.

− Desafíos

  • Programarlo es más complejo.
  • Hay que sincronizar lo compartido.
  • Los fallos son difíciles de reproducir.

Dónde se usan

Interfaces de usuarioServidores web · un hilo por conexiónAudio y vídeo en tiempo real

03 · Hilos en Java
07

Dos formas de crear un hilo,
un solo botón para arrancarlo.

A · Implementar Runnable

class Tarea implements Runnable {
  public void run() {
    System.out.println("Hola");
  }
}

Thread t = new Thread(new Tarea());
t.start();

B · Extender Thread

class MiHilo extends Thread {
  public void run() {
    System.out.println("Hola");
  }
}

new MiHilo().start();

Con lambda: new Thread(() -> ...).start()

start() crea el hilo. run() a secas solo ejecuta el método, sin hilo nuevo.

03 · Hilos en Java
09

Sin sincronizar,
el error es intermitente.

class Contador {
  private int c;

  // c++ = leer, sumar, escribir
  void inc() { c++; }

  synchronized void incS() { c++; }
}

2 hilos · 1 000 000 sumas cada uno · esperado: 2 000 000

Sin synchronized

1 de 20

ejecuciones erróneas · llegó a dar 1 028 410

Con synchronized

0 de 20

siempre 2 000 000

Medido en Java 27, 20 núcleos. Que casi nunca falle es justo lo que hace tan difícil depurarlo.

05 · Problemas clásicos
12

Productor y consumidor
comparten un búfer.

synchronized (cont) {
  while (!cont.datoDisponible())
    cont.wait();
  dato = cont.get();
  cont.notify();
}

Cada uno avisa al otro al cambiar el estado del búfer.

Mal hecho (sleep/wakeup sin monitor) el aviso se pierde y ambos duermen para siempre.

esperando permiso

Cuando uno hace release(), el hilo 3 entra. Semaphore(1) se comporta como un mutex.

Semaphore sem = new Semaphore(2);

sem.acquire();   // pide permiso

sem.release();   // lo devuelve
acquire()
espera si no hay
release()

05 · Problemas clásicos
15

Cinco filósofos, cinco tenedores
y un interbloqueo.

Para comer hacen falta dos tenedores. Si todos cogen primero el de su derecha, nadie puede comer y nadie suelta.

Cómo se rompe el bloqueo

  • Romper la simetría: uno coge los tenedores en orden contrario.
  • Coger los dos a la vez: un método synchronized en la mesa; si falta uno, wait().
